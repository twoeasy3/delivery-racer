# Car catalogue

Every car in Delivery Racer, with what it is and the real vehicle it is inspired by. Started 14-Oct (the owner: "keep a file of
all the car names and a description of what they are / inspired by") so that agents stop proposing duplicates.

## The rule

**An agent proposing a new car must first grep this file for the vehicle AND for its real-world inspiration** (the maker, the
model, the nickname: `grep -in "beetle\|volkswagen\|vw" CARS-CATALOGUE.md`), then say in its draft which rows it checked. A hit
means the car exists or is in progress: do not propose it again. (The People's Bug exists, so no Bug Saloon; the Cinquecento is
the Fiat 500, so no second Fiat 500.) Two cars of the same real vehicle in different guises are a duplicate too.

## How it is organised

One table per group, one row per car: `id | name | what it is / inspired by | source`. The groups follow the code: 1 garage cars
(`CARS` by tier, gold stars and Blue Star; the amphibious cars; the Tank; Super cars are the garage cars in a livery, listed
nowhere), 2 filler (blueprint) cars, 3 Bespoke key cars (and concept cars), 4 earned cars (level-earned, and Legendary),
5 event cars, 6 secret cars, 7 level vehicles, 8 traffic kinds (`CONFIG.vehicles`), 9 idea cars (`ideas.js`), 10 cars in progress
on other branches. Each table is preceded by a `<!-- group:NAME -->` line that `scripts/car-catalogue.mjs` reads: keep it.

The inspiration column starts with the real vehicle (or what it looks like), then ` - ` and a short line about the car. The
**source** column is honest about where the inspiration comes from:

- `basedOn field`: the entry's own `basedOn` in the game data (idea, filler, Bespoke and Legendary cars have one).
- `code comment`: the comment above the model's builder in `render/*.js` or above the entry in `cars.js` / `config.js` names the vehicle
  ("a Golf GTI, more or less"). Where the comment names only a class (a kei truck, a funeral hearse), the row says so.
- `note`: the entry's `note`, or the owner's brief (the in-progress rows).
- `inferred from name/model`: nobody wrote the inspiration down; the row says what it looks like and the guess is ours. Treat it
  as a hint, not a fact, and replace it when someone reads the model.

## Keeping it up to date

Agents do NOT edit this file (new cars land on parallel branches, and edits here would conflict on every merge). The orchestrator
adds the rows when it merges a car branch: put the row in the right group table, with the real `id`, the `name` from the game, the
inspiration (the entry's `basedOn`, which every idea entry must set) and the source; delete the matching "in progress" row.

Run `node scripts/car-catalogue.mjs` by hand after a merge (it is a warning script: always exit code 0, in no test group). It
lists ids in the game that are missing from this file, ids here that no longer exist, names that differ, and possible
near-duplicates (rows sharing a real-world inspiration keyword). `--rows` prints ready-to-paste rows for the missing ids.
